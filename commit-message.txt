feat(sandbox): add atomic apply_patch/revert_patch with path traversal guards

Implement apply_patch and revert_patch in src/repro/sandbox/patcher.py.

apply_patch(ws, patch) -> (applied: bool, message: str):
- Prefer `git apply --check` then `git apply` inside the workspace when
  it is a git repo; fall back to a pure-Python unified diff applier
  otherwise
- Atomic by construction: snapshot the affected files before applying,
  and restore them if any hunk fails, so the workspace is byte-identical
  to its pre-call state on any failure
- Validate every path in the diff is inside the workspace before
  applying anything, using the same traversal rules as B1
- Never raise on a malformed diff; return (False, reason) instead

revert_patch restores the pre-patch state from the snapshot.

Add tests/test_patcher.py covering:
- Clean apply
- Apply then revert returns to the original tree hash
- A diff with a bad hunk leaves the tree untouched
- A diff referencing ../../ is rejected
- A diff touching a nonexistent file is rejected

Hash the whole tree before and after for the atomicity tests.
